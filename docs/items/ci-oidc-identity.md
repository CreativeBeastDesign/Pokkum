# CI OIDC identity for provenance

| Field | Value |
| --- | --- |
| Status | open |
| Stage | v1.2 |
| Kind | feature |
| Tier | foundation |
| Area | Supply Chain & Attestation |

## Summary

Bind SLSA provenance to an issuer-attested CI OIDC identity instead of a self-asserted one from a developer laptop.

## Problem

Provenance generated by the CLI on a developer laptop is SLSA L1/L2 in substance regardless
of what the attestation claims, since nothing external attests to the build environment.
First-class GitHub Actions / GitLab / Buildkite OIDC would make the certificate identity
issuer-attested rather than self-asserted, and state the build environment explicitly in
the attestation. This is what actually separates a real SLSA L3 claim from an asserted one.

## Options

| Option | Description | Tradeoffs |
| --- | --- | --- |
| Read the platform's OIDC token directly | Detect GitHub Actions/GitLab CI/Buildkite env vars, fetch the platform's own OIDC token, and fold the resulting identity into the SLSA statement's builder.id. | No new external dependency, but three platform-specific code paths to maintain and keep current as each platform's token format evolves. |
| Delegate to Sigstore's existing Fulcio/OIDC flow | Reuse the same Fulcio certificate-issuance flow already vendored for keyless base-image verification, pointed at signing instead. | Less new code, but ties CI-identity binding to Sigstore's keyless *signing* path landing first (see [KMS-backed signing](kms-signing.md) is a separate axis, not a prerequisite). |
