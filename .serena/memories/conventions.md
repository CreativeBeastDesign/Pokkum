# Codebase Conventions & Architecture Rules

- **Hexagonal Architecture Rules**:
  - `internal/ports` is the leaf node of the internal dependency graph. It imports standard library + `go-containerregistry/pkg/v1` only. It must NEVER import `internal/core` or any adapter.
  - Compile-Time Port Assertions: All concrete Hexagonal adapters MUST declare explicit compile-time interface assertions (e.g., `var _ ports.X = (*Y)(nil)`) to guarantee immediate compile-time detection of port contract drift.
  - Automated purity verification is implemented in `internal/architecture_test.go` and enforced via `go test ./internal/...` or `make check-arch`.
  - `internal/core` imports `internal/ports` and standard library. It re-exports boundary vocabulary as type aliases (`core.Platform = ports.Platform`).
  - `internal/adapters/*` import `internal/ports` and `internal/core` (for sentinel errors).
  - `cmd/pokkum` is the composition root where concrete adapters are instantiated.
- **Shared Registry HTTP Transport (`internal/adapters/transportutils`)**:
  - `transportutils.CloneDefaultTransport(tlsConfig *tls.Config) http.RoundTripper` is the SINGLE home for the HTTP transport every registry adapter runs on: it clones `remote.DefaultTransport` (preserving `http.ProxyFromEnvironment`, 30s dial, `MaxIdleConnsPerHost: 50`, `ForceAttemptHTTP2: true`) and applies a `TLSClientConfig` override only to the clone.
  - Registry adapters MUST NOT write bare `&http.Transport{}` literals — a literal silently drops go-containerregistry's tuning (no proxy, 2-conn idle pool, and no HTTP/2 on insecure paths where a custom `TLSClientConfig` suppresses the auto h2 upgrade). All `--insecure`/`Insecure: true` paths go through the shared `transportutils.InsecureTransport()`.
  - `transportutils.InsecureTransport()` returns the single process-wide insecure transport (a clone of `remote.DefaultTransport` with `InsecureSkipVerify: true`), lazily built once via `sync.OnceValue` and shared across `registry` (`insecureTransport`), `baseimage` (`insecureTransport`), and `remotecacheutils` (sig fetch / `CheckRemoteCache` / `ReconcileTags`) so one-shot calls share one connection pool; `transportutils.CloneDefaultTransport(tlsConfig)` is the lower-level builder for a custom-config clone (e.g. `defaultTransport = CloneDefaultTransport(nil)`). Treat the shared insecure transport as read-only. Declares `const IsUtilityPackage = true`.
  - Note: net/http has no h2c client support, so a plain `http://` insecure target stays HTTP/1.1 regardless of this helper (stdlib limitation).
  - See `Lessons.md` for the `http.Transport.Clone()`/`nextProtoOnce` subtlety that makes clone-based fixing safe on insecure paths.
- **`sync.Pool` Buffer Recycling (`internal/adapters/poolutils`)**:
  - Manages `sync.Pool` allocation recycling for 64KB I/O copy buffers (`GetCopyBuffer`, `PutCopyBuffer`, `Copy`) and bounded `bytes.Buffer` instances (`GetByteBuffer`, `PutByteBuffer` capped at 1MB).
  - Eliminates heap allocation churn across tar archiving (`packager`), layer caching (`layercacheutils`), input hashing (`remotecacheutils`), and static asset pre-compression (`precompressutils`).
- **Composite Remote OCI Input Caching & Anti-Poisoning Verification (`internal/adapters/remotecacheutils`, `ports.RemoteCacher`)**:
  - EXPLICITLY REVIEWED & SIGNED-OFF TRADEOFF (2026-02): On a confirmed remote-cache hit, base-image signature verification (`BaseImageResolver.VerifyBaseImage`) is intentionally SKIPPED — the cache-hit short-circuit at pipeline stage 4.5 returns before stage 5 runs `VerifyBaseImage`/`NativeInspector.Inspect`. Rationale: nothing is built from the base image on a hit; the composite input hash already binds the base image DIGEST (`base.Digest`, pinned via `pokkum.lock`) into the cache key, so a hit can only match the exact-same base image the verifier would have checked. Two independent signature checks protect different layers: `VerifyBaseImage` authenticates the base image bytes (upstream publisher); `CacheVerify` (remotecacheutils.Check) authenticates the cached OUTPUT image (`<repo>:cache-<hash>`) a prior pokkum build pushed (anti cache-poisoning). Accepted residual risk: on a cache hit, an attacker who can (a) forge a valid `cache-<hash>` image signature AND (b) use the exact pinned base image digest — i.e. already trusted to push to the repo — could inject a cache entry, but they would need the same signing key/identity as a legitimate build and identical build inputs. **This "same signing key" framing is weaker than it reads** (found 2026-08-18, see `Lessons.md`'s image-signing entry and the placeholder-key gap noted just above): `internal/adapters/cosign/signer.go`'s `DefaultPublicKeyPEM` and `internal/adapters/baseimage/resolver.go`'s `DefaultBaseImagePublicKeyPEM` are byte-identical — one hardcoded placeholder key is the last-resort fallback across signing verification, base-image verification, AND remote-cache verification alike, whenever an operator hasn't set the relevant `POKKUM_*_PUBKEY` env var. It is a real, valid P-256 key so parsing never fails, and it fails closed (nothing was ever actually signed with its private half, so nothing verifies against it by accident) — but it means "the same signing key as a legitimate build" is not a meaningfully high bar by default; it is whichever operator-configured key each of the three independent env-var chains happens to fall back to when unset, not a per-domain secret. Splitting the placeholder per domain, or removing the fallback in favor of a hard failure when no real key is configured, is tracked as open in `Roadmap.md`. Regression-guarded by `TestBuild_CacheHit_SkipsVerifyBaseImageAndNativeInspection`. To keep the tradeoff visible/auditable, the cache-hit path also emits an explicit INFO log line disclosing the skip with the base ref+digest (`"cache hit; base image signature verification skipped (not built from base)"`, or a note when `--no-verify-base` is set) — guarded by `TestBuild_CacheHit_DisclosesBaseImageVerificationSkip`.
  - Computes deterministic composite input hashes (`sha256(source + lockfile + baseDigest + bunVersion + platforms + flags)`).
  - Queries target repository for `<repo>:cache-<input-hash>`. Prior to promoting release tags, cryptographically verifies Cosign static-key or Sigstore keyless signatures on the candidate image (`<repo>:<alg>-<hex>.sig`).
  - On verified hit, retags requested release tags and returns `BuildResult{Cached: true}` in sub-100ms, skipping SvelteKit bundling and layer tarring.
  - On unverified/tampered candidate, cleanly bypasses cache and falls back to a clean source build. In strict mode (`--cache-verify-strict`), fails the build.
  - Signed builds can safely hit the cache when candidate images carry verified signatures matching trusted credentials.
  - Escape hatch: `--no-cache` forces full rebuild; `--no-cache-verify` disables pre-promotion signature verification.
  - **Real gap, exposed rather than closed by image signing landing 2026-08-18** (see `mem:core`'s signing entry and `Lessons.md`): this cache-hit verification's public key comes from its own resolution chain — `--cache-verify-key`/`POKKUM_CACHE_PUBKEY` → `POKKUM_SIGNING_PUBKEY` → `POKKUM_BASE_IMAGE_PUBKEY` → the shared embedded placeholder (`cosign.DefaultPublicKeyPEM`) — which `internal/core/pipeline.go`'s `RemoteCache.Check` call never populates from `req.Signing.PublicKeyPEM` (the actual key that just signed the build). An operator using `--signing-key` to sign real builds but not ALSO separately setting `POKKUM_CACHE_PUBKEY`/`POKKUM_SIGNING_PUBKEY` gets fail-safe behavior (a real signature won't verify against the placeholder, so the candidate is rejected and the build falls through to a full rebuild) but not the "signed builds safely hit the cache" acceleration the bullet above describes. Not yet fixed.
- **ELF Native Addon Stripping (`internal/adapters/striputils`)**:
  - Automatically strips unneeded debug symbols from native `.node` addons and `.so` shared libraries in `/app/native` and `/app/vendor`.
  - Stripping occurs strictly inside `.pokkum/` sandbox directories, preserving user workspace source code.
  - Sets pinned `SOURCE_DATE_EPOCH` timestamps on stripped files.
  - Escape hatch: `--no-strip` disables native addon debug symbol stripping.
- **Build-Time Static Asset Pre-Compression (`internal/adapters/precompressutils`)**:
  - Generates `.gz` (Gzip, via `github.com/klauspost/compress/gzip`, not stdlib), `.br` (Brotli quality 11), and/or `.zst` (Zstandard best compression) sidecars for compressible assets (`.js`, `.css`, `.html`, `.json`, `.svg`, `.wasm`, etc.) in `/app/client`/`/app/prerendered`, per `PrecompressOptions{Gzip, Brotli, Zstd bool}` — the layered strategy requests gzip+brotli only (its sirv server never negotiates zstd); `--strategy=static` requests all three.
  - Pre-compression executes strictly inside the `.pokkum/` build sandbox (`OutputDir/client`), ensuring zero mutation of user source files.
  - Sidecars inherit pinned `SOURCE_DATE_EPOCH` timestamps.
  - Escape hatch: `--no-precompress` disables static pre-compression.
- **Single-Pass Layer Hashing & Streaming (`internal/adapters/packager`)**:
  - Computes uncompressed `DiffID` and compressed `Digest` concurrently during a single tar generation stream via `buildSinglePassLayer`.
  - Eliminates 2-3 redundant disk reads and multiple compression passes, answering `v1.Layer` queries in `O(1)` time with byte-for-byte deterministic reproducibility.
- **Pre-Calculated & Cached Immutable Layers (`internal/adapters/layercacheutils`)**:
  - `layercacheutils` caches compressed immutable layer blobs (`/usr/local/bin/bun`, `/pokkum/init`) in `~/.cache/pokkum/layers/` (or `$POKKUM_CACHE_DIR/layers`), saving ~100MB of tarring and gzip/zstd compression per build.
- **Compressed Embedded Supervisor Binaries (`internal/adapters/supervisor`)**:
  - `make supervisor` cross-compiles `pokkum-init` for linux amd64/arm64 into a temp staging dir and embeds them zstd-compressed (`.zst`, best compression) into `bin/`, removing raw ELF so `go:embed all:bin` embeds ~4.7MB instead of ~12MB.
  - `ports.SupervisorProvider.Binary`/`Version` decompress on-the-fly via a shared lazy `zstd.Decoder` (`supervisorDecoder`, `sync.OnceValue`) and a `decodeSupervisor` seam; raw binary output is owner-owned and concurrency-safe.
  - `Version()` hashes the decompressed raw amd64 bytes, so supervisor version labels are unchanged for identical binaries.
  - Empty or corrupt embedded blobs yield `errSupervisorCorrupt` (distinct from `core.ErrSupervisorUnavailable` for an absent asset), so `Binary()` never returns empty bytes on a nil error.
  - Compressor helper: `scripts/compress-zstd.go` (single-shot `EncodeAll`, `SpeedBestCompression`), deterministic for reproducible releases; no external zstd CLI dependency.
  - Cache keys are deterministically computed via `ComputeKey(targetPath, contentSHA256, platform, modTime, compression)`.
  - Automatic fallback to temp directories or in-memory layer generation if disk cache is unwritable.
- **Vendor Layer Pruning & Zero-Mutation Sandbox (`internal/adapters/pruneutils`)**:
  - Automatically strips junk files (`*.d.ts`, `*.map`, `tsconfig.json`, `README*`, tests) during vendor layer (`/app/vendor`) archiving, reducing image size by 15–35MB.
  - Guarantees zero mutation to user's working directory / source `node_modules` (pruning only runs on build sandbox / layer tar stream).
  - Escape hatches: `--no-prune` completely disables pruning; `--keep-vendor=<glob>` whitelists specific patterns; `--sourcemap` preserves `*.map` files.
- **Runtime Env Contract (`Tier 3 Post-v1.0`)**:
  - `--require-env=KEY1,KEY2` on `pokkum build` declares required runtime environment variables. Stamped in OCI manifest annotations (`pokkum.dev/required-env`), labels (`dev.pokkum.required-env`), and injected as `POKKUM_REQUIRED_ENV` in the container environment. The PID-1 supervisor (`/pokkum/init`) enforces presence at startup, failing fast before binding probe ports or starting the application.
- **Fake Implementation Strict Verification & Documentation Policy**:
  - Fake, stub, or mock implementations must NEVER be assumed or reported as completed; any simulated logic must be explicitly flagged.
  - Keep `Roadmap.md`, `ARCHITECTURE.md`, `Vocabulary.md` (human-readable) and Serena MCP (`mem:*` for agents) continuously in sync.
  - Propose "Next Best Steps" after each completed implementation based on `Roadmap.md` / `AdditionalFeatures.md`.
- **Live Cluster Annotation Inspection & Multi-Generation Rollback (`Tier 3 Post-v1.0`)**:
  - `pokkum apply` queries live cluster state (`kubectl get <kind>/<name> -n <ns> -o json`) before manifest resolution (`--cluster-inspect`, `--no-cluster-inspect`) to extract active annotations and seed `pokkum.dev/image-history` and `pokkum.dev/previous-image`, enabling seamless multi-generation history accumulation across independent CLI runs on static `pokkum://` templates.
  - `pokkum rollback` supports multi-generation rollback via `pokkum.dev/image-history` annotations in Kubernetes manifests with timeline listing (`--list`) and generation depth (`--generation=<n>`, `-g <n>`).
  - `pokkum history <image>` inspects SLSA v1.0 attestations, Cosign signatures, and builder metadata, extracting links to GitHub Actions CI workflow runs, Pull Requests, and commits.
- **Day-2 Operations & CI/CD Ecosystem (`v1.0 MVP Bundle 8`)**:
  - `pokkum rollback -f <manifest> [--to=<ref>]` rolls back image references in Kubernetes manifests using declarative `pokkum.dev/previous-image` annotations or an explicit target `--to` reference.
  - `pokkum upgrade [--check]` checks for new Pokkum CLI releases, verifies release `checksums.txt` and `checksums.txt.sig` via `ports.ReleaseVerifier` (implemented in `cosign.Signer`), and reports or applies binary self-updates. Supports `--version`, `--offline`, and `--key`.
  - `.github/actions/setup-pokkum/action.yml` exports the composite GitHub Action for automated CI setup.
- **Enterprise Build Integrity & Hermetic Mode (`v1.0 MVP Bundle 7` & `Tier 2 Post-v1.0`)**:
  - Hermetic Build Mode (`pokkum build --hermetic`) enforces zero-network egress during compilation (`BUN_OFFLINE=1`), forces offline base image resolution (`--offline`), and checks local `node_modules/` pre-population (`core.ErrHermeticViolation`).
  - Multi-Registry Auth Config (`--registry-config=<path>`) is supported across `build`, `resolve`, `apply`, and `verify` for private registries, cloud credential helpers (`credHelpers`, `credsStore` executing `docker-credential-*` binaries like ECR, GCR, OSXKeychain with in-memory caching), and static `auths` blocks via `registryutils.ResolveKeychain` taking primary precedence over `authn.DefaultKeychain`.
  - Ephemeral OCI 1.1 Test Registry Utility is exported at `pkg/registry.NewServer()` and wired as the canonical test registry factory in `tests/integration/harness_test.go` (`NewRegistryHarness`) with `WithHandlerWrapper` middleware support.
- **Security Scanning & Base Image CVE Build Gate (`v1.0 MVP Bundle 6` & `Tier 1 Post-v1.0`)**:
  - `pokkum scan [target]` subcommand runs security scans against project directories, container images, or tarballs. Catalogs OS packages via lightweight zero-dependency native parsers (`scannerutils`) and queries OSV.dev in high-performance batches (`/v1/querybatch`). Flags: `--fail-on=low|medium|high|critical` (default `critical`), `--toolchain` (OSV advisory lookups for embedded Bun and SvelteKit), `--output=text|json`, `--offline`, `--allow-incomplete` (default fails closed if database lookup fails).
  - Base Image CVE Reactivity & Build Gate: `pokkum build` actively scans base images on resolve and warns or fails (`--fail-on-cve=critical|high|medium|low`, `POKKUM_FAIL_ON_CVE`), with fail-closed incomplete scan handling (`--allow-incomplete` opt-out) and audit updates into `pokkum.lock` (`last_scanned_at`, `vulnerabilities_count`, `max_severity`); `pokkum doctor` checks locked base images against known CVEs.
  - Base Image Escrow Mirroring: `pokkum base update --mirror-registry=<repo>` mirrors base images/indexes and their Cosign `.sig` tags to a project-controlled registry, saving `mirror_ref` in `pokkum.lock` with automatic fallback. Mirror write errors are classified (`core.ErrPushFailed`/`core.ErrRegistryAuth`) and fail-closed so `pokkum.lock` never records unwritten mirror refs.
  - Base Image Signature Verification & Escrow Compatibility: Enabled by default (`VerifySignature: true`); queries registry for signature tags (`<repo>:sha256-<hex>.sig`) and verifies cryptographic payload signatures via `ports.CosignSigner` (`cosign.Signer`) or keyless Sigstore. When resolving escrow-mirrored bases (`--mirror-registry`), Cosign signature claims (`docker-reference`) are checked against the upstream repository from `pokkum.lock`'s `Ref` field while fetching images/signatures from the mirror, ensuring full verification and digest integrity without false docker-reference mismatch errors; `--no-verify-base` provides opt-out.
  - Secret-Inlining Guard (`secretguard`) runs build-time entropy and pattern scanning across project sources during `pokkum build` before packaging layers, preventing hardcoded secret leaks (`core.ErrSecretInlined`). Pass `--allow-secret-pattern=<regex>` to bypass false positives.
- **Migration & Adoption Tooling (`Tier 3 Post-v1.0`)**:
  - `pokkum adopt [dir]` migrates existing SvelteKit repositories (configured for `@sveltejs/adapter-node`, `adapter-vercel`, `adapter-auto`, `adapter-cloudflare`, etc.) to Pokkum compilation defaults. Rewrites `svelte.config.js` and `package.json`, bootstraps `.pokkumignore`, and optionally deletes legacy container artifacts (`--remove-dockerfile`). Supports `--dry-run` and `--output=json`. Implemented in `internal/adapters/sveltekitutils.Adopt`.
- **Project Configuration & Build Profiles (`.pokkum.yaml`, `ports.ConfigManager`)**:
  - `.pokkum.yaml` defines top-level build defaults (repo, base preset, strategy, platforms, image metadata/labels/env/ports, security gates, SBOM, cache) and named workflow profiles (`map[string]ports.BuildProfile`, e.g. `local`, `production`).
  - Precedence hierarchy: explicit CLI flags > environment variables (`POKKUM_*`) > active profile overrides (`--profile <name>` or automatic `local` profile on `--local`) > top-level `.pokkum.yaml` defaults > built-in defaults.
  - Port/Adapter interface: `ports.ConfigManager` implemented by `internal/adapters/config` (`Manager`).
  - Subcommands: `pokkum init` bootstraps `.pokkum.yaml` and `.pokkumignore` with interactive terminal questionnaire (and `--defaults` mode); `pokkum config view` (with `--profile`) and `pokkum config validate` inspect and validate project configurations.
- **Structured JSON Schema Standard (`--output=json`)**:
  - Global `--output=text|json` flag standardizes CLI stdout into versioned `ports.JSONEnvelope` payloads (`schema_version: "1.0"`).
- **Cluster Hardening & Manifest Defaults (`v1.0 MVP`)**:
  - `pokkum resolve` and `pokkum apply` inject hardened `securityContext` defaults (`runAsNonRoot: true`, `seccompProfile: RuntimeDefault`, `allowPrivilegeEscalation: false`, `capabilities.drop: [ALL]`), container resource limits/requests (`requests: cpu 50m, memory 64Mi`; `limits: memory 256Mi`), and append `NetworkPolicy` (with dynamic containerPort ingress rules and egress restricted to DNS 53, HTTPS 443, and OTLP 4317/4318) and `PodDisruptionBudget` documents by default.
- **Custom & Standard OCI Image Annotations**:
  - `pokkum build` supports `--image-label key=value` (repeatable) to inject custom user labels, auto-populating OCI annotations (`org.opencontainers.image.*`).
- **Rebuild Verification & Diagnosis (`v0.5` / `Tier 0`)**:
  - `pokkum verify` performs genuine SLSA attestation checks (`--no-rebuild`) and bit-for-bit rebuild verification (`--against <tarball>`) across L1 (exact manifest hash), L2 (semantic uncompressed DiffIDs and config), and L3 (tar stream layer diffs with root-cause diagnostics) via real `provenance.Resolver` and `comparator.Comparator` adapters. Enforces DSSE envelope verification and rejects unsigned in-toto statements.
- **Base Image Lockfile (`pokkum.lock`)**:
  - `pokkum.lock` stores pinned SHA256 digests of base images (`distroless`, `chainguard`), along with `last_scanned_at`, `vulnerabilities_count`, and `max_severity` audit metadata.
- **Determinism**:
  - Adapters must never call `time.Now()` or read system clocks. All timestamps derive from `req.SourceDateEpoch`.
- **Compiler Build Optimization Flags (`-trimpath -ldflags="-s -w"`)** (Roadmap #132): every `pokkum` / `pokkum-init` binary is compiled with `-trimpath` (strips absolute source-path leakage) and `-ldflags="-s -w"` (strips DWARF/debug info) in ALL release paths — `Makefile` `build`/`supervisor` targets, `.goreleaser.yaml` (official `pokkum upgrade` release pipeline), and `.github/workflows/slsa-builder.yml` (SLSA L3 trusted-builder path). All three also set `-X main.version/commit/buildDate` so `pokkum version` reports real metadata (SLSA resolves from git; goreleaser via template vars). Build-config concern, NOT CLI flags. Guarded against silent regression by `scripts/check-build-flags.sh`, wired in as Step 0 of `make verify`.
- **Fast Supervisor Startup Overlap (`supervisor/cmd/pokkum-init`)**: `main.go` resolves the child executable up front via `resolveChildPath` and passes it to `New(cfg, log, WithChildPath(path))`, so `start()` forks immediately with no `exec.LookPath` on the fork path while the probe server binds `/healthz` on its own goroutine — the probe bind and the Bun fork/exec overlap instead of serializing (roadmap "Fast Sub-Millisecond Supervisor Startup"). `Supervisor.childPath` is set once at `New` and read only on the pinned-thread `start()`, so it needs no locking. The pre-resolved failure path preserves the exact 126/127 `startExitCode` mapping (`errors.Is` still resolves through the `%w` wrap). Guarded by `startup_test.go` (`TestProbeServesWhileChildIsRunning`, `TestResolveChildPathFailureMapsToStartCodes`); suppress-proof invariant: signal handlers are installed and `runtime.LockOSThread()` held before `os.StartProcess`, and `os/exec.Cmd.Wait` must never be introduced (single `wait4(-1)` reaper).
- **Monorepo Affected-Detection (`--since` on `resolve`/`apply`)**:
  - `internal/adapters/gitutils` (utility pkg, `const IsUtilityPackage = true`) implements `ports.AffectedDetector` (`NewAffectedDetector(baseDir)`): runs `git diff --name-only <ref> -- .` scoped to each project dir plus `git status --porcelain -- .` (so untracked/staged/deleted changes count as affected), validates `--since` via `rev-parse --verify <ref>^{commit}`, fail-closed on unknown ref / git error.
  - `ports/ResolveRequest` gained `Since string` + `AffectedDetector`; `ports.Reference` gained `Skipped bool`.
  - `k8s.Resolver.Resolve` gates each distinct path: when `Since != ""` + detector set and the project is unaffected AND a prior digest is known (`findExistingImageForPath`: manifest `pokkum.dev/current-image` annotation on template/doc-root → live-cluster annotation → live-cluster container image; only accepts refs containing `@sha256:`), it records the digest in `resolvedMap`/`skippedMap` and skips the build; otherwise falls through to `req.Build`. Requires every emitted ref to be `repo@sha256:…`.
  - `imageNodeTarget` stores `docRootNode` (the enclosing document root) enabling per-target cluster queries via cached `queryClusterState(clusterCache, inspector, docRoot)` (dedup keyed by kind/ns/name; failures not cached). Cluster-write-pass still surfaces exactly one `ClusterInspectionWarning` per workload on inspector error.
  - `cmd/pokkum/k8s.go` wires `--since` → `resolveManifestsOptions.Since` and defaults `AffectedDetector = gitutils.NewAffectedDetector(baseDir)` when `Since != ""`; logs `reused unaffected image reference` for `Reference.Skipped`.
